# Trade website template

A lead-generation website for local trades (builders, roofers, landscapers…), built once and reused per client.

- **Next.js 16** (App Router, TypeScript) and **Tailwind CSS 4**, hosted on **Vercel**
- **Sanity** CMS embedded at **`/studio`**: text, images, videos, services, FAQs, quote-form answers and SEO are editable
- **Supabase** (Postgres + Storage) stores every quote request, with a **`/admin`** leads dashboard (status, notes, CSV, Google Ads offline conversions)
- **Resend** sends the owner a scored lead summary and the customer an auto-reply
- Google Tag Manager / GA4 / Google Ads with Consent Mode v2, loaded **only after cookie consent** and only in production (see `TRACKING.md`)

The template ships with a **fictional demo client** (`clients/demo-builder`, "Demo Build Co") on the **loft & extension** trade pack.

## How it fits together

| Folder | What it holds |
|---|---|
| `clients/<slug>/` | One client: `config.ts` (name, colours, location, review site, storage prefix), `brand.tsx` (logo, favicon), `content/` (starter settings, areas, pages, privacy policy) |
| `packs/<slug>/` | One trade: services, guides, FAQs, quote-form questions, lead scoring, email wording, area-page text. See [docs/NEW-PACK.md](docs/NEW-PACK.md) |
| `config/` | The `ClientConfig` type and helpers |
| `clients/active`, `packs/active` | Generated by `scripts/select-client.mjs`. **Don't edit by hand** |

Pick the client with `CLIENT=<slug>`. This runs automatically before `dev`, `build`, `test` and `typecheck`. With no `CLIENT` set, the committed selection (`demo-builder`) is used.

## Quick start

```bash
npm install
cp .env.example .env.local
npm run dev
```

The site opens at http://localhost:3000. Needs Node.js 20 or newer.

On Windows PowerShell, run each command on its own line, and use `npm.cmd` if scripts are blocked.

With no keys set, the site runs locally on fallbacks:

| Feature | With keys | Without keys (development only) |
|---|---|---|
| Content | Sanity (`NEXT_PUBLIC_SANITY_PROJECT_ID`) | The client's starter content |
| Leads + uploads | Supabase (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, server-side only) | `.data/leads.json`. **Refused in production**: the form asks visitors to call instead |
| Email | Resend (`RESEND_API_KEY`, `EMAIL_FROM`) | Written to `.data/outbox.json` |
| Tracking | GTM / GA4 / Ads IDs (production only) | Off, with no banner |

In production, a startup check refuses to run without the required settings and lists what's missing (see `.env.example`).

## Commands

| Command | What it does |
|---|---|
| `npm run dev` / `build` / `start` | Develop, build, serve |
| `npm test` | Unit tests (Vitest) |
| `npx playwright test` | Browser tests (builds and serves the demo client) |
| `npm run typecheck` | TypeScript |
| `npm run check:leaks` | Fails if client data or placeholders would leak into the template or a production build |
| `npm run make:pdf` | Builds the active client's checklist PDF from its pack |
| `npm run parity` / `parity:compare` | Snapshot rendered pages and compare two snapshots (no visible text changes) |
| `npm run seed:sanity` | Copy the active client's starter content into a new Sanity dataset |
